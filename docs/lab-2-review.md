# Ревью и завершение лабораторной № 2

Материалы подготовлены в lab-2. Автор не одобряет собственный PR. При индивидуальной работе содержательное ревью выполняет студент другой команды по назначению преподавателя. Одобрение product преподавателем и approve PR — разные действия; одно не заменяет другое.

## Перед отправкой

Проверить документ 1.0, семь PNG и исходники, таблицу README, CHANGELOG. Commit и push выполняет владелец самостоятельно. Пример сообщения: `document FR-1 to FR-8 NFR-1 to NFR-5 and US-1 to US-8 with system models`. Тег lab-1, если ещё не поставлен, нужно поставить на коммит слияния ЛР1, а не на будущий коммит ЛР2.

## Текст pull request

Заголовок: `describe requirements and system models for lab 2`

Подготовлена версия 1.0 спецификации HelpDesk Go:

- [О приложении и требования](docs/01-requirements.md#1-о-приложении): роли, термины, текущее и планируемое поведение, FR-1–FR-8 и NFR-1–NFR-5.

- [Модели](docs/01-requirements.md#4-модели-системы): контекст, деятельность, варианты использования, две последовательности, модель данных, состояния; PlantUML и PNG.
- README содержит статусы, CHANGELOG — запись о документе 1.0.

Открыто для согласования: запрет повторного открытия и переназначения, запрет комментариев в closed, начальное наполнение учётных записей и категорий. Связанные вопросы: #2, #3, #4. Документ описывает целевой контракт, функциональность прототипа не расширялась.

Проверка: исходники диаграмм экспортированы PlantUML 1.2025.2; проверены ссылки, количество требований и покрытие сценариями. Программный код не менялся.

## Порядок ревью

1. Открыть PR lab-2 → main, назначить review и рецензента.
2. Рецензент: Files changed → комментарий к конкретной строке, затем Review changes → Request changes либо Approve по результатам проверки. Не использовать формальное «всё хорошо» вместо содержательного замечания.
3. Автор отвечает на каждое замечание; исправление — отдельным коммитом со ссылками FR/NFR/US и issue при наличии. Обоснованное отсутствие изменения также фиксируется ответом.
4. Закрыть обсуждения после ответа и исправления, дождаться approve всех рецензентов.
5. Слить PR и поставить lab-2 на итоговый коммит main. Не ставить тег до слияния. Запись 1.0 в CHANGELOG уже подготовлена, статус выпуска обновить по факту.

Ревью, комментарии, ответы, approve, слияние и тег не считаются выполненными до реальных действий участников на GitHub.
