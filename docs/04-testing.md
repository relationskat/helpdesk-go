# Автоматические проверки

## Область проверки — лабораторная № 4

Выбрана работающая операция POST /tickets из [контракта ЛР3](interface-contract.md), связанная с FR-2 / US-2. Это тестирование существующего прототипа, а не подтверждение реализации всего FR-2 или NFR-5.

| ID | Тест | Вход | Ожидаемый результат |
| --- | --- | --- | --- |
| T-1 | TestCreateTicketSuccess | title="  Не работает VPN  ", новое хранилище | 201, application/json, ID=1, title="Не работает VPN", status=open; GET списка содержит ровно эту заявку |
| T-2 | TestCreateTicketBlankTitle | Сначала одна заявка, затем title="   " | 400, text/plain; charset=utf-8, точный текст ошибки с LF; список не меняется, следующая созданная заявка имеет ID=2 |

Реализация: [tickets_test.go](../src/internal/api/http/tickets_test.go). Используется httptest.ResponseRecorder, реальный HTTP-роутер и новое хранилище в памяти. Внешних сервисов нет, фиксированные порты не открываются.

Локально: `go mod download`, `go test -count=1 -v ./src/...`, `go vet ./src/...`. Контейнерный вариант описан в [README](../README.md#разработка). Область ./src/... включает весь исходный код приложения; посторонние файлы вне src не входят в эти проверки.

## GitHub Actions

[ci.yml](../.github/workflows/ci.yml): pull_request в main, события opened, synchronize, reopened. Шаги: checkout, Go 1.24.5 из .go-version, go mod download, тесты без кеша результатов (-count=1), дополнительный статический анализ go vet. Право workflow — только чтение содержимого. Сторонних библиотек нет, кеш зависимостей выключен, go.sum не требуется.

## Демонстрация ошибки и исправления

Для демонстрации в одном PR временно задаётся неверное ожидание T-1; после красного прогона правильное значение восстанавливается отдельным коммитом. До публикации и фактического запуска нельзя считать задачу 3 выполненной. Локальная проверка намеренно неверного ожидания не заменяет красный прогон GitHub Actions.

Полная программа тестирования остальных функций дополняется в следующих работах; T-1 и T-2 сохраняют номера.
