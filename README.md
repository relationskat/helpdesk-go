# HelpDesk Go

Система заявок технической поддержки, новый индивидуальный проект по программной инженерии.
Репозиторий: https://github.com/relationskat/helpdesk-go. Лицензия: [MIT](LICENSE).

Роли: заявитель и специалист поддержки. Четыре сущности и восемь функций описаны в [паспорте](docs/00-project.md). ЛР1: запускаемый скелет; требования ещё не согласованы, идентификаторы UR/FR/NFR вводятся с ЛР2. Сейчас доступны создание и список заявок без авторизации; данные живут в памяти до перезапуска. Прототип предназначен для локальной проверки.

## Запуск

Нужны Git, Docker с запущенным daemon; для проверки — POSIX shell и curl. Компилятор, стандартная библиотека и встроенная система сборки: Go 1.24.5 (`go.mod`, `.go-version`). Внешних Go-зависимостей нет, `go.sum` не требуется. Образ сборки `golang:1.24.5-alpine3.22`, runtime `scratch`. Docker CLI в рабочей среде — 29.2.1. Образ сборки закреплён версионным тегом и SHA-256 digest в Dockerfile. Runtime не требует установленных библиотек.

От чистого клона — пять команд:

```sh
git clone https://github.com/relationskat/helpdesk-go.git
cd helpdesk-go
git switch lab-1
docker build -t helpdesk-go:lab-1 .
docker run --rm -p 127.0.0.1:8080:8080 helpdesk-go:lab-1
```

Установка зависимостей и сборка выполняются внутри Docker. Остановка — Ctrl+C. После слияния работ тег `lab-1` будет обозначать итоговый коммит.

В другом терминале из каталога проекта: `sh tests/smoke.sh`. Три шага: `GET /healthz`, создание через `POST /tickets`, поиск созданной заявки в `GET /tickets`. Успех: `PASS: health, create ticket, find created ticket`. Каждый запуск добавляет демонстрационную заявку.

Автоматическая проверка в новом Linux-контейнере: `sh scripts/check-container.sh`; нужен свободный порт 18081. Контейнер удаляется после проверки. Без Docker с Go 1.24.5: `go run ./src/cmd/helpdesk`. Конфигурация: `ADDR` (по умолчанию `127.0.0.1:8080`, в контейнере `:8080`); `BASE_URL` — адрес для smoke-сценария.

## Структура кода

`src/cmd/helpdesk/main.go` собирает зависимости. В `src/internal/` выделены `config`, `api/http` (сервер, роутер, обработчики), `api/http/dto`, `domain`, `service` и `store`. HTTP-слой преобразует JSON в вызовы сервиса, сервис проверяет заголовок заявки, хранилище отвечает за данные и синхронизацию. Подробная карта — в паспорте проекта.

## Статус требований

Пользовательские и функциональные требования пока предварительные: согласованы будут в лабораторной № 2 в `docs/01-requirements.md`. UR-n, FR-n, NFR-n, CR-n и T-n вводятся начиная с этой работы. Функции карты, кроме демонстрационных создания и списка, планируются к реализации; поддержка ролей пока отсутствует.

## Разработка

`go vet ./...`, `go test ./...`, `sh scripts/check-container.sh`. Модульных тестов пока нет: `go test` проверяет сборку, HTTP smoke проверяет основную функцию. Форматирование — gofmt. Конфигурация GitHub Actions добавлена, успешное выполнение удалённого CI ещё нужно подтвердить.

Каждая лабораторная выполняется в `lab-N`, включается в `main` через PR; тег `lab-N` ставится на итоговый коммит после слияния. Замечания — issues, исправляющие коммиты ссылаются на номер issue. Идентификаторы UR/FR/NFR/CR/T — с ЛР2. Сообщения коммитов содержательно описывают задачу; в этом проекте используются английский язык и маленькая начальная буква. [История изменений](CHANGELOG.md).

Тексты issues и шаги настройки защиты main: [docs/issues/README.md](docs/issues/README.md). Product остаётся открытым до реального одобрения преподавателем проекта и плана.
